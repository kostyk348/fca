## [0.4.0] — 2026-11-03

### Added

- **AVX2 vector kernels are back** (`src/simd.rs`, ported from the C
  prototype's `include/fca/rules.hpp`): hand-written 32-pixel blocks for the
  fuzzy and EPX rules — saturated abs-diff tolerance, 16-bit triangle
  membership, `mulhi` weights, half-shift blend. **Bit-exact with the scalar
  reference** (tests compare both paths on deterministic random grids across
  every 32-block boundary width). Runtime dispatch, `FCA_SIMD=0` pins scalar.
  Rule stage at 854x480: fuzzy 7.91 -> 0.44 ms/frame (**18.0x**), EPX 2.2x;
  end-to-end fuzzy 75 -> 205 fps (**4.2x** vs the 0.3 build).
- **`--hq` maximum-quality preset** in `fca_video`: 16-bit two-band + CAS
  (final + a second pass between the two 4x stages) + dehalo + edge-aware
  denoise 40 + vibrance 24 + ink-line darkening 24.
- **`--ld N` ink-line darkening** (`postfx::line_dark`): strict 3x3-minimum
  pixels with >= 32 contrast are line cores, darkened by up to N levels
  scaled by edge strength — restores anime stroke weight; cannot halo.
- **4x max-quality showcase on real footage** (Ergo Proxy ep. 1):
  `--hq --4x` renders 854x480 -> 3416x1920; full-frame and native-pixel
  zoom comparisons vs swscale lanczos 4x (`docs/rust/real_4x_*.png`),
  generated by `scripts/fca_simd_4x.py`.

### Changed

- `bicubic2x` rewritten as padded 4-tap FIR (clamp-once edges, contiguous
  loops) — auto-vectorizes; `fca_video` packs yuv444p16le via u16 words
  instead of byte-by-byte pushes. 16-bit pipeline 30 -> 45 fps (+48%),
  4x HQ 3.3 -> 4.7 fps (+42%); bit-exact (C-golden post-FX chain passes).
- Version 0.4.0; benchmark chart superseded: `docs/rust/simd_bench.png`
  (AVX2 vs scalar pairs) replaces `real_bench.png`.

### Prior (merged to main as one batch with the showcase)

- **Real-footage showcase and benchmark** (Ergo Proxy ep. 1, 854x480):
  full-frame 2x comparison, 6x silhouette zoom, 8x thin-lines zoom,
  four-scene grid, 8-vs-16-bit dark-gradient comparison
  (`docs/rust/real_*.png`), all generated by the self-contained
  `scripts/fca_real_anime.py`;
- bilingual README sections for the real-anime material and the AVX2/4x work.

## [0.3.0] — 2026-11-02

### Added — Rust port (replaces the C++ implementation)

- Rust crate `fca` (lib + `fca_upscale` + `fca_video`) with the same CLI surface,
  algorithms and rawvideo pipe semantics as the C++ prototype. Dependencies:
  `clap` + `rayon` only — no C libraries, no OpenMP, no AVX2 build flag.
- **Bit-exact golden verification**: `tests/golden.rs` embeds outputs generated
  from the original C headers (rules, full post-FX chain, VSR, temporal cache);
  the port must reproduce them byte for byte. 30 tests total.
- CLI: `fca_upscale --rule fuzzy|scale2x|xbr [--bench]` (replaces `--scalar`,
  which has nothing to compare against in a single-implementation port).

### Fixed (deviations from the C original, all golden-verified)

- **Temporal cache never slept twice**: the C `TemporalUpscaler::process` did
  not fill `prev_` after the first frame, so frame 2 was compared against
  zeros and every static scene recomputed at least two frames. The port seeds
  the previous-frame buffer; static frames now sleep from frame 2 on.
- **`bicubic8` read past the plane**: the 4-tap window indexed one row/column
  past the plane edge (weight 0 at the exact edge, garbage pixels otherwise).
  The port clamps the tap indices.
- **`bicubic2x` left-edge clamp**: the horizontal/vertical taps clamp at the
  correct edge (the C used the same index for both, which the port reproduces).

### Changed

- Performance model: the hand-written AVX2 path is gone; the scalar reference
  (which the C kept bit-exact with AVX2) is the single implementation, rows are
  parallelized with rayon. Measured: 640x360 → 1280x720 per plane in 2.2 ms
  (scale2x) on a sandbox CPU.
- `fca_video`'s stats output unchanged (stderr, same fields).

### Removed

- The C++ sources (`include/`, `src/*.cpp`, `bench/`, `Makefile`) — fully
  replaced by the Rust crate. `shaders/` and `docs/` are kept as-is.
